文件上传漏洞实战：从无验证到 Getshell 的完整流程

一、什么是文件上传漏洞 文件上传漏洞是指 Web 应用程序允许用户上传文件，但没有对上传文件的类型、内容、后缀等进行充分校验，导致攻击者可以上传恶意文件（如 Web Shell），进而控制服务器的安全漏洞。 1.1 漏洞的本质 正常业务场景中，用户上传头像、文档、图片等文件，服务端将其保存到服务器目录。如果服务端信任了用户上传的所有文件，攻击者就可以上传一个伪装成图片的 PHP 脚本，然后直接访问该脚本执行任意代码。 1.2 典型的漏洞代码 // 无验证的文件上传 $target = "upload/" . basename($_FILES["file"]["name"]); move_uploaded_file($_FILES["file"]["tmp_name"], $target); 这段代码直接将用户上传的文件保存到 upload/ 目录，不做任何类型检查。上传 shell.php 后，访问 http://target.com/upload/shell.php 即可执行恶意代码。 二、常见应用场景 文件上传漏洞通常出现在以下业务场景中： 2.1 用户头像/资料上传 社交平台、论坛、博客系统允许用户上传头像、背景图。如果仅检查文件扩展名或 MIME 类型，攻击者可以通过修改后缀、伪造 MIME 等方式绕过。 2.2 附件与文档管理 企业 OA 系统、邮件系统、网盘允许上传文档、压缩包。如果服务端对压缩包内的文件不做二次检查，攻击者可以上传包含 Web Shell 的 ZIP 文件。 2.3 编辑器与富文本组件 富文本编辑器（如 UEditor、KindEditor）的图片上传功能，如果没有严格限制上传类型，可能成为 getshell 的入口。 2.4 API 文件接口 前后端分离架构中，前端通过 API 上传文件到 OSS 或服务器。如果 API 没有校验文件类型，攻击者可以直接调用接口上传任意文件。 三、环境判断：确定用什么木马 上传木马前，必须先判断目标环境的语言和中间件，否则上传的木马无法执行。 3.1 判断方法 方法 操作 示例 URL 后缀 观察页面 URL index.php → PHP Wappalyzer 插件 浏览器插件自动检测 显示 PHP、Apache、Nginx 响应头 查看 X-Powered-By X-Powered-By: PHP/7.3.14 报错页面 触发 404 或报错 Fatal error: Uncaught Error → PHP 3.2 常见木马类型 环境 木马后缀 示例 PHP .php <?php eval(@$_POST['a']); ?> JSP .jsp <% Runtime.getRuntime().exec(request.getParameter("cmd")); %> ASP .asp <% eval request("cmd") %> ASPX .aspx <%@ Page Language="Jscript" %> 四、一句话木马原理 4.1 PHP 一句话木马 <?php eval(@$_POST['a']); ?> 执行逻辑： ...
