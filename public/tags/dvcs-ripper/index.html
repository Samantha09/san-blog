dvcs-ripper 与 Mercurial (.hg) 信息泄露漏洞详解

前言 Mercurial（简称 hg，化学元素汞的符号）是一种分布式版本控制系统，与 Git 类似，广泛应用于代码管理。和 .git、.svn 一样，当开发人员将包含 .hg 目录的项目直接部署到 Web 服务器根目录，且未做访问限制时，攻击者就可能通过下载 .hg 目录中的元数据，恢复源代码、历史版本，甚至获取敏感信息。 本文将介绍 .hg 信息泄露漏洞的原理、使用 dvcs-ripper 自动化挖掘漏洞的过程，以及对应的 防护措施。 一、漏洞原理 1.1 .hg 目录结构 Mercurial 在每个仓库的根目录下维护一个 .hg 目录，用于存储版本控制所需的全部元数据。其核心结构如下： .hg/ 00changelog.i # 变更日志索引，记录所有提交历史 dirstate # 工作目录状态（哪些文件被跟踪、修改、删除） requires # 仓库格式版本要求 branch # 当前分支名 last-message.txt # 上次提交信息 undo.branch # 撤销操作相关 undo.desc undo.dirstate store/ # 核心数据存储区 00changelog.i # 提交历史的 revlog（索引） 00changelog.d # 提交历史的 revlog（数据，大文件时存在） 00manifest.i # 清单文件的 revlog（记录每个版本中包含的文件列表） 00manifest.d # 清单文件的数据部分 fncache # 文件名缓存，记录所有被跟踪文件对应的 revlog 路径 undo # 撤销数据 data/ # 各文件的历史版本 revlog index.html.i # index.html 的 revlog 索引 index.html.d # index.html 的 revlog 数据（大文件时存在） flag_xxxx.txt.i # 其他文件的 revlog 索引 flag_xxxx.txt.d # 其他文件的 revlog 数据 1.2 Revlog 存储机制 Mercurial 使用 revlog（revision log）格式来存储所有版本数据。每个被跟踪的文件都有一个对应的 revlog，由一对文件组成： ...

SVN 信息泄露漏洞原理、利用与防护

SVN 信息泄露漏洞原理、利用与防护 一、什么是 SVN 信息泄露漏洞 SVN（Subversion）是一种集中式版本控制系统，广泛用于代码管理。在 Web 开发中，开发者常常直接将包含 .svn 目录的项目部署到 Web 服务器的根目录下。如果服务器没有正确配置访问控制，攻击者就可以通过浏览器直接访问 .svn 目录下的文件，从而获取网站的源代码、历史版本、敏感配置甚至数据库密码，这种安全问题被称为 SVN 信息泄露漏洞。 二、漏洞原理 2.1 .svn 目录的作用 SVN 在每个工作副本（Working Copy）的根目录下维护一个隐藏的 .svn 目录，用于存储版本控制所需的元数据。这些元数据包括： 仓库地址（Repository URL） 文件版本信息 完整的文件历史内容（pristine 副本） 本地修改状态 作者、提交时间等日志信息 2.2 旧格式（SVN 1.6 及更早） 在旧版本中，.svn 目录分散在每个子目录中，结构如下： .svn/ entries # 文件/目录列表及版本信息 format # 工作副本格式版本号 text-base/ # 当前版本文件的原始副本 prop-base/ # 属性文件 props/ # 本地修改的属性 tmp/ # 临时文件 关键风险点：entries 文件以明文形式记录目录结构和版本号，text-base/ 下存储着当前版本所有文件的完整原始内容。即使服务器禁止了目录遍历，攻击者仍可以直接猜测并下载这些文件。 2.3 新格式（SVN 1.7+） 从 SVN 1.7 开始，工作副本改为单 .svn 模式，所有元数据集中在根目录的 .svn 中： ...
