极简主义

Gemini 协议：Gopher 的精神继承者与极简 Web 的另一种可能

一、Gemini 是什么 Gemini 是一种新兴的互联网应用层协议，诞生于 2019 年，由 Solderpunk 发起设计。它的定位非常明确： 介于 Gopher 和 HTTP 之间，比 Gopher 更现代，比 HTTP 更简单。 如果你厌倦了现代 Web 的臃肿——动辄几 MB 的 JavaScript、无穷无尽的 Cookie 弹窗、追踪脚本和广告框架——Gemini 提供了一条回归信息本质的逃生通道。 二、为什么需要 Gemini 2.1 Gopher 太古老 Gopher（1991）的设计理念很棒（极简、层级、纯文本），但它有硬伤： 无加密：明文传输，在现代互联网不可接受 无错误码：成功失败靠约定，调试困难 无类型系统：资源类型靠单个字符标识，扩展性差 无输入机制：除了搜索框，几乎无法与用户交互 2.2 HTTP 太复杂 HTTP/1.1 → HTTP/2 → HTTP/3，每一次迭代都在增加复杂度： 特性 HTTP 现状 Header 数十个标准头，无限自定义头 方法 GET/POST/PUT/PATCH/DELETE/OPTIONS… 状态码 40+ 个，还要细分 扩展 Cookie、CORS、HSTS、CSP、SRI… 渲染引擎 HTML + CSS + JS，永恒的安全噩梦 Gemini 的设计哲学是有意识地做减法： “不是 HTTP 做不了的我们不加，而是 Gopher 没做好的我们才补。” 三、Gemini 的核心设计 3.1 协议栈极简 +------------+ | Gemini | ← 应用层协议（类似 HTTP） +------------+ | TLS 1.2+ | ← 强制加密（类似 HTTPS） +------------+ | TCP | ← 传输层 +------------+ Gemini 强制 TLS，没有明文传输的选项。这避免了 HTTP 历史上 “HTTP 默认、HTTPS 可选” 的安全债。 ...
